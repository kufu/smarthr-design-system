ユーザーに操作の結果を伝えるUIの基準を定義します。

ユーザーが行った操作へのシステムからの応答をフィードバックと呼びます。メッセージを画面上に表示したり、コンポーネントの意匠を変更するなどの方法が取られます。

## 基本的な考え方
### ユーザーが受動的に結果を認識できるようにする

フィードバックはユーザーが操作の結果を理解し、次の行動を判断するために重要です。ユーザーが何らかの操作をした際はその結果を受動的に認識できるように、素早く画面上にフィードバックのためのUIを表示してください。

#### フィードバックを省略できるケース
以下の例のように画面の変化から操作が成功していることが**明らかに理解できる場合のみ**フィードバックのためのUIは省略します。

- ページの読み込みに成功したタイミング
- 新規追加したオブジェクトの詳細ページが自動で開かれる場合

### 操作部の近くでフィードバックする

ユーザーは画面の全領域の変化に常に気づくとは限りません。可能な限り、直前までユーザーが操作していた要素の近くか、コンポーネント自体の変化で操作の結果をフィードバックします。

特に拡大鏡を利用する弱視・ロービジョンのユーザーは、拡大表示範囲外の変化を認識できません。

関連ページ：
- [弱視・ロービジョン | アクセシビリティインサイト](/accessibility/insight/low-vision/)
- [エラーなどの重要な通知は操作部の近くで表示する | 弱視・ロービジョンのユーザビリティチェックリスト](/accessibility/insight/low-vision/notification-proximity/)

### スクリーンリーダーでの読み上げ順序を考慮する

スクリーンリーダーは原則として、ページの内容をHTML要素が記述された順序で読み上げます。そのため、視覚的なデザインだけでなく、HTMLの記述順が文脈として適切かを確認してください。

### ライティング
エラー状態をフィードバックする場合、[エラーメッセージの基本的な要素](/products/contents/error-messages/overview/#h2-0)に沿ったメッセージを表示してください。エラー状態はユーザーの目的達成を阻害するため、回復方法が理解できるライティングが重要です。


## 種類
操作の結果をフィードバックする代表的な状況は以下のとおりです。  
なお、非同期処理のフィードバックについては、[バックグラウンド処理](/products/design-patterns/background-jobs-results/)を参照してください。

- フォームを入力・送信するとき
- 同期的な処理を開始したとき
- 同期的な処理が完了したとき
- ページ・要素の読み込みを開始したとき
- ページ・要素の読み込みが完了したとき

### フォームを入力・送信するとき

#### 入力時に値が不正であることを判定する場合

入力要素からフォーカスが外れたタイミングで、入力要素に対してエラーメッセージを表示します。値が修正され、エラーの原因が解消された場合はエラーメッセージの表示を止めます。

入力要素に対するエラーメッセージは、[FormControl](/products/components/form-control/)か[Fieldset](/products/components/fieldset/)の`errorMessages`で表示します。入力要素にも`error`状態を付加して意匠を変化させます。

```tsx editable hideCode withStyled
const TITLE_MAX_LENGTH = 50
const DEFAULT_TITLE = 'これはタイトルです。'.repeat(6)

const validateTitle = (title: string) =>
  [...title].length > TITLE_MAX_LENGTH ? `タイトルは${TITLE_MAX_LENGTH}文字以下で入力してください。` : undefined

const ValidateOnBlurForm = () => {
  const [title, setTitle] = React.useState(DEFAULT_TITLE)
  // 入力要素からフォーカスが外れた直後の状態を示すため、初期状態からエラーメッセージを表示している
  const [errorMessage, setErrorMessage] = React.useState(validateTitle(DEFAULT_TITLE))

  return (
    <Stack
      as="form"
      align="flex-start"
      onSubmit={(e) => {
        e.preventDefault()
        setErrorMessage(validateTitle(title))
      }}
    >
      <FormControl label="タイトル" errorMessages={errorMessage}>
        <Textarea
          name="title"
          value={title}
          maxLetters={TITLE_MAX_LENGTH}
          width="30em"
          rows={3}
          error={!!errorMessage}
          onBlur={() => {
            // フォーカスが外れたタイミングで値を検証する
            setErrorMessage(validateTitle(title))
          }}
          onChange={(e) => {
            const { value } = e.currentTarget
            setTitle(value)
            // エラーの原因が解消されたら、エラーメッセージの表示を止める
            if (errorMessage && !validateTitle(value)) {
              setErrorMessage(undefined)
            }
          }}
        />
      </FormControl>
      <Button type="submit" variant="primary">追加</Button>
    </Stack>
  )
}

render(<ValidateOnBlurForm />)
```

#### フォームの送信時に値が不正であることを判定する場合

送信ボタンの押下後に、入力要素と送信ボタンに対してエラーメッセージを表示します。エラーの原因が解消された場合はエラーメッセージの表示を止めます。

入力要素に対するエラーメッセージは、[FormControl](/products/components/form-control/)か[Fieldset](/products/components/fieldset/)の`errorMessages`で表示します。入力要素にも`error`状態を付加して意匠を変化させます。

送信ボタンに対するエラーメッセージは、`error`状態の[ResponseMessage](/products/components/response-message/)（[ActionDialog](/products/components/dialog/action-dialog/)の場合は`responseStatus`）を利用して表示します。

```tsx editable hideCode withStyled
const DEFAULT_TITLE = 'Aさんの情報$'

const validateTitle = (title: string) =>
  title.includes('$') ? '利用できない文字「$」が含まれています。' : undefined

const ValidateOnSubmitForm = () => {
  const [title, setTitle] = React.useState(DEFAULT_TITLE)
  // 送信ボタンを押した直後の状態を示すため、初期状態からエラーメッセージを表示している
  const [errorMessage, setErrorMessage] = React.useState(validateTitle(DEFAULT_TITLE))

  return (
    <Stack
      as="form"
      align="flex-start"
      onSubmit={(e) => {
        e.preventDefault()
        // 送信ボタンを押したタイミングで値を検証する
        setErrorMessage(validateTitle(title))
      }}
    >
      <FormControl label="タイトル" errorMessages={errorMessage}>
        <Input
          name="title"
          value={title}
          error={!!errorMessage}
          onChange={(e) => {
            const { value } = e.currentTarget
            setTitle(value)
            // エラーの原因が解消されたら、エラーメッセージの表示を止める
            if (errorMessage && !validateTitle(value)) {
              setErrorMessage(undefined)
            }
          }}
        />
      </FormControl>
      <Cluster align="center">
        <Button type="submit" variant="primary">追加</Button>
        {errorMessage && <ResponseMessage status="error">入力内容に不備があります。</ResponseMessage>}
      </Cluster>
    </Stack>
  )
}

render(<ValidateOnSubmitForm />)
```

### 同期的な処理を開始したとき

実行した[Button](/products/components/button/)を`loading`状態に変化させます（[ActionDialog](/products/components/dialog/action-dialog/)の場合は`responseStatus`を利用）。

処理が完了したら表示を切り替え、[同期的な処理が完了したとき](#h3-5)のフィードバックを表示します。

```tsx editable hideCode
<Stack as="form" align="flex-start" onSubmit={(e) => e.preventDefault()}>
  <FormControl label="タイトル">
    <Input name="title" defaultValue="Aさんの情報" />
  </FormControl>
  {/* 処理中は実行したButtonをloading状態にする */}
  <Button type="submit" variant="primary" loading>追加</Button>
</Stack>
```

操作後に画面全体の切り替えが発生する場合など、処理を実行したButtonの状態変化で伝えることが難しい場合は、`sync`状態の[NotificationBar](/products/components/notification-bar/)を表示します。

処理が完了したら表示を切り替え、[同期的な処理が完了したとき](#h3-5)のフィードバックを表示します。

### 同期的な処理が完了したとき

ユーザーが直前に操作していたButtonなどの近くに、成功時には`success`状態、失敗時には`error`状態で[ResponseMessage](/products/components/response-message/)を表示します。再度処理を実行するタイミングでメッセージの表示を止めます。

```tsx editable hideCode background=BACKGROUND
<Cluster gap={4}>
  <Cluster align="center">
    <Button>実行</Button>
    <ResponseMessage status="success">処理に成功しました。</ResponseMessage>
  </Cluster>
  <Cluster align="center">
    <Button>実行</Button>
    <ResponseMessage status="error">処理に失敗しました。</ResponseMessage>
  </Cluster>
</Cluster>
```
